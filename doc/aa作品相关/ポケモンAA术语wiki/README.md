## 三点五、补充术语.json（人工增量，唯一手改入口）

`术语表.json` / `官方译名对照.json` 是**生成物**，勿手改——手写条目一律写进 `补充术语.json`，`--build` 时合并（同 `jp` 时人工条目优先），重建 wiki 不会丢。

```jsonc
{
  "terms": [                                   // 通用补充：跨作品通用
    {"jp":"技マシン","zh":"招式学习器","cat":"道具","page":"补充（说明对齐）","note":"来源/取舍理由"}
  ],
  "works": {                                   // 作品专属：只有该作用得到的译名
    "<作品名>": {
      "terms":   [{"jp":"ソノオスタジアム","zh":"花苑竞技场","cat":"场地","note":"ソノオタウン=花苑镇"}],
      "effects": [{"jp":"《{竞技场}》のフィールド効果","zh":"《{竞技场}》的场地效果","cat":"场地模板"}]  // {…} 为槽位，仅作图鉴说明
    }
  },
  "修正": [                                    // 按 jp 覆盖已有条目的 effect/desc/zh（抽取器踩坑时的兜底）
    {"jp":"チェイサー","desc":"自身的攻击招式附带「追打」效果。","src":"依据/为什么改"}
  ]
}
```

- **通用补充怎么来**：ポケマス 说明里 `effect`（日）与 `desc`（中）是平行文本，按 `「」『』《》` 成段对齐即可捞出「说明里早有中文、但缺日中对」的条目（例：`技マシン → 招式学习器`、`持ち物 → 持有物`、`とくこう → 特攻`）。对齐脚本产出候选，人工确认后写入本文件。
- **作品专属为什么单独放**：竞技场/队伍/地名这类只在单部作品里出现的名字，混进全局表会跨作品污染（同一假名在不同作品可能对应不同中文）。放在 `works.<作品名>` 下，只在该作品翻译时注入。
- **对翻译的影响**：`scripts/common/pre_terms.py`（宝可梦链翻译前强制替换）读这两个来源 → `src=wiki-补充` / `src=作品专属`，本章语料里真出现的词才替换；`作品专属` 与 `wiki-补充` 允许整句（≤60 字），便于场地效果这类模板句整体落地。
- **`修正` 段是干什么的**：抽取器实测会踩三种坑——①`『X』付随` 是役割家族的**类型标记行**，曾被当成说明（`desc` 变「附带」）；②`オリジナル技` 表里 AA 自己就没填（`effect = ---`）；③长句被按行截断（`『エンペラー』は「Ｓ」…` 丢了主语）。三种都在 `--build` 时靠这一段覆盖；条目里写 `effect` / `desc` / `zh` 的才会被覆盖，`src` 写依据。
- **`desc` 会被当正文用，必须写干净译文**：`scripts/common/pokemon_fixed.py` 的 struct 轨在章节里命中 `『名』…说明` 时，**直接拿 wiki 的 `desc` 预填**（按源列位 pad）——所以 `desc` 里不要写「（※…）」这种注释（注释放 `src`），否则会原样进正文。
- **改完必须重建**：`python scripts/tools/gen_pokemon_aa_wiki.py --build`（离线，只读 `_raw/` 缓存）→ 刷新 `index.html` / `术语表.json`，pre_terms 的缓存按文件 mtime 自动失效。
- **构建期体检**：`--build` 最后会打印「⚠ 可疑 desc N 条」（占位串/比原文短太多/残留平假名/无说明行却还挂着旧译文），清单里的 `jp` 直接粘进 `修正` 段即可。当前 0 条。


## 四、生成管线（4 段，均可断点续跑）

```bash
# 全部（抓取→提取→翻译→构建）；各段也可单独跑
python scripts/tools/gen_pokemon_aa_wiki.py --all
python scripts/tools/gen_pokemon_aa_wiki.py --crawl-pk   # 只抓 ポケマス（缓存命中即跳过）
python scripts/tools/gen_pokemon_aa_wiki.py --crawl52    # 只抓 52poke 官方表（列表页：现被登录墙挡，用缓存）
python scripts/tools/gen_pokemon_aa_wiki.py --crawl-places  # 只抓 52poke 地名（地区+城镇，可用）
python scripts/tools/gen_pokemon_aa_wiki.py --extract    # 解析 → terms_raw.json / official.json
python scripts/tools/gen_pokemon_aa_wiki.py --translate  # 模型翻译 → terms_zh.json / pages_zh.json
python scripts/tools/gen_pokemon_aa_wiki.py --build      # 生成 index.html + 两个 JSON
```

- 抓取：BFS 从菜单页种子展开，**跳过读者投稿页**（`僕の考えた○○/…`）与已知空页；已缓存页不再请求。
- 翻译：走 `aa_backend.call_with_fallback` 现用模型链（本次=官网 `deepseek-flash`），术语按 12 条/批、系统页按 25 行/批并发 8；JSON 解析失败自动二分重试；**结果按日文名缓存**，重跑只补缺口。
- 空页/缺页在 `--extract` 阶段打印 `- 无此页` / `! 缺页`，不会污染数据。
- 本次成本：`pokewiki` tag **474 次调用 · 356K 输入 / 171K 输出 · 约 ¥2.03**（`python scripts/tools/usage_stats.py --cost --days 1`）。

## 五、统一译名口径（重要）

1. **官方优先**：AA 术语名若与官方招式/特性/道具/宝可梦/属性同名，一律取 52poke 官方中文，不另起译名。
2. **AA 原创术语**：按字面意译，保留游戏化措辞（`优先度` `架势` `设置技` `必中技` `反作用力` `期` 等）。
3. **效果说明**：逐句直译，保留原文括号注、百分比（`3割 → 三成/30%` 与原文并存）、回合数（`T → 回合`）、全角「」引号结构；招式/特性/属性/状态名一律用本表统一译名。
4. **期别后缀**保留：`（四期）` `（五期）` `（変更後 → 修改后）` 等直接随名翻译，便于区分同名的不同期版本。
5. **系统页**逐行对齐翻译（行数与原文一致），因此可切换日文原文做对照；不合并、不改行数。
6. 译名一旦发现偏差，**只改 `_raw/terms_zh.json` 中该条**（键=日文名，值 `{"zh":…,"desc":…}`）再 `--build` 即可覆盖，不必重跑翻译。

## 六、与本地 AA 汉化管线的衔接

- `术语表.json` / `官方译名对照.json` 可作为 Pokémon 题材作品的**术语候选来源**（配合 `gen_glossary_ai.py` 的候选池、`glossary_<work>.json` 的人工确认流程）。
- `官方译名对照.json` 用于防止译名漂移，口径与「查维基→萌娘」的角色译名规范一致（宝可梦官方译名以 52poke 为准）。
- ⚠️ 本 wiki **不会自动注入**任何作品术语表——沿用既有铁律「作品术语表只手动维护」，需要时人工挑选后写入该作品的 `glossary_<work>.json`。

## 七、已知局限

- **只收术语与系统页**，不收 ポケマス wiki 的读者投稿页（`僕の考えた○○/ポケモン/…`，数百页）与作品正文。
- 菜单里部分页名是占位（如 `減衰（期間）`），实际不存在，已跳过；空页一并跳过。
- 快照为 2026-09-22，原站更新后需重跑 `--crawl-pk`（新页会被抓，旧页读缓存）。
- 翻译为模型产出（未逐条人工校订），专有名词可能有偏差；发现后按 §5.6 单条覆盖。
- 属別ポテンシャル等长表里，个别条目原文说明本身缺失（表格空单元格），对应中文说明也为空。
