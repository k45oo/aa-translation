# 楼主楼嵌字方案（2026-08-14 grilling 定稿 + 第一轮实现验证）

> 背景：M15 落地后楼主楼（◆帖头）整楼冻结不加大。用户提出"楼主楼文字加大用嵌字方案"：
> 先替换文字为特殊颜色符号 → 图片生成后用加大文字覆盖（文字+2 与用户内容一致）。
> 经 grilling 逐项决策定稿，**第一轮已实现并验证**（36/90 块生效），剩字号策略待用户拍板。

## 用户原提案的致命问题（事实核查）
- 特殊色锚点（洋红/青）过 PNG-8 固定调色板量化后 **100% 丢失**（被映射成灰 162,161,157）——
  用户方案第一步就被 M15 末尾启用的 PNG-8 压缩杀死。嵌字必须在 quantize **之前**做（渲染器内部），
  且坐标在绘制时就在内存里，直接记录 bbox 即可，**特殊色锚点整个不需要**。

## 9 项决策（用户逐项拍板）
| # | 决策 | 选择 |
|---|---|---|
| 1 | 范围 | 楼主楼 text + mixed 台词都加大 |
| 2 | 精准识别 | 渲染期坐标记录（弃特殊色锚点）+ line_meta_v2 segments 段级分类 |
| 3 | 落地 | A1 嵌字重绘（艺术段像素不动）——**否决 A2 段级字号**：行中/行左台词加大后错位，用户明确"这种错位非常影响观感" |
| 4 | 安全策略 | B 全部嵌字硬上，压 AA 可接受，文字周边留背景色空隙（否决"只对纯背景段嵌字"——用户接受压画） |
| 5 | 宽度预算 | 同步放大：block_layout 预估时 text 段按 fs+2 算，永不裁边（否决"超宽就裁"→截台词；否决"字号自适应"→参差） |
| 6 | 字体 | SimHei 统一（与用户楼一致；否决保持 PGothic→SimSun 明体语义——全书台词字体要统一） |
| 7 | 清除区域 | 整段矩形 + 外扩 2px（文字被小背景框托住，观感干净；否决逐字符 bbox——边缘锯齿化、观感碎裂） |
| 8 | 行高 | 同步 +2（与 M15 用户楼行高逻辑一致；否决行高不变→大字压上下行**文字**会糊，压 art 可接受但压字不可接受） |
| 9 | 作用范围 | 嵌字只对楼主楼；用户楼保持已验证的行级加大（零回归；嵌字对纯文本行级场景无优势） |

## 精准识别数据源（关键发现）
- **`さーきー/work_fc2/line_meta_v2/` 有现成段级分类**（73 章全覆盖）：每行 `{kind, confidence, reason, segments:[{start,end,kind,src_width,confidence}]}`
  ——mixed 行才有 segments；纯 text/art 行只有整行 kind+confidence。text 段 conf 0.55~0.93。
- ⚠️ **v2 是旧版分类器，短台词误判 art 与 M15 已修问题同源**：真实短台词 228 行中 13 行被判 art，
  全部 reason 为 `lz_text_lt5`（楼主楼 <5 字）或 `anon_text_lt2`（用户楼 <2 字）——
  如 `３．奈良`、`草`、人名 `松実宥`/`宮永照`/`新子憧`。v2 没吃到 line_classify 的 5→2 修复。
- 判 text 的行 confidence 全部 ≥0.93 → 门槛 0.7 不会误伤 text 行（用户担忧"门槛挡真台词"不成立）。
- 用户担忧"少量文字和语气词被识别为 aa"**真实存在**（正是 lz_text_lt5 类）→ 需要兜底。

## 收尾决策（最后一个问题，未拍板，推荐 A）
嵌字判定 = ①v2 segments 的 text 段（conf≥0.7）**或** ②整行被判 art 但 reason 是 `*_lt*`（短文本规则）
且汉化后含连续中文 → 反转回 text 也嵌字。即：**v2 段级分类为主 + 短台词规则兜底**。
- 兜底判据干净：汉化后含连续中文 = 模型只译文本行（管线铁律"艺术行绝不进模型"），`奈良`/`草` 这类短台词命中。
- 否决 B（门槛 0.7 不兜底 → 短台词不加大，长/短台词字号参差）；否决 C（改 v2 分类器本身，影响面大）。

## 其他核查结论
- ckpt（翻译快照）**不是干净地面真值**：混入占位艺术行，且 txt 被 pass2/补译修改后行内容失联。
- is_text_line 双向误判：艺术脸 `／（ー） （ー）＼` 判 True（该 False）、骰子 `【1D10:3】` 判 False（该 True）。
- YOLO/OCR：不需要且有害——坐标在渲染期已知，用模型猜已知信息是负收益；AA 无现成数据集。
- 嵌字垂直对齐 = 行高同步 +2 后大字不出行；骰子红/粗体段嵌字需带原样式（坐标记录同时存 color/bold）。

## 实现入口（若立项）
- `render_block` 绘制循环里按 line_meta_v2 segments 记录 text 段 bbox + style → 全部行画完后对楼主楼 text 段
  执行：矩形+2px 填背景 → SimHei fs+2 大字重绘 → 贴回；quantize(PALETTE8) 必须在嵌字之后。
- 验收：楼主楼 text/mixed 台词可见加大、art 段像素 0 位移（嵌字只覆盖文字区域）、无超出画布、
  关键色 0 缺失（嵌字在量化前不影响调色板）。

# 第一轮实现记录（2026-08-14 已完成并验证）

## 实现
- `render_block(..., embed_v2=None)`：新增参数 + 嵌字执行段（绘制完整块后）：
  对 embed_jobs 逐条 `d.rectangle([x0-2, y_base-2, x1+2, y_base+int(fs*LINE_RATIO)+2], fill=BG)` 清背景
  → SimHei fs+2 `d.text` 重绘（bold 位移双印）；**位置在 ink 裁剪与 quantize 之前**。
- `v2_text_spans(v2_line, txt)`：识别函数，返回 [(start,end)] 字符区间（v2 的 start/end 是**原行 txt 字符索引**，
  含前导空格；嵌字时用 `pick()` advance 逐字符累加映射到像素 x）。
- 坐标映射：`advs = [(c, pick(c, fs, use_sh)[1]) for c in txt]` → pos 数组 → span 切片取 pos[s0]/pos[s1]；
  样式（color/bold）按 line_segments 段偏移定位（seg_offsets 累加 len(seg_text) 匹配 s0 落在哪段）。

## 识别逻辑 3 轮修复（成功→失败→收敛，每条都是坑）
1. ❌ **纯中文正则兜底误嵌纹理**：`_HAN2_RE = [\u4e00-\u9fff]{2,}` 把 art 纹理行
   `二二二二`/`八芹坏`/`爻从艾`（AA 轮廓用汉字）判成台词 → 整行嵌字毁画面（块0001 39 处误嵌）。
2. ❌ 纹理字表补全仍不够：加 `卞込刈辷厂心` 等仍漏（`八_人 ァ卞卞ト` 的"卞"）。
3. ✅ **最终收敛 = 双条件**：兜底仅当 v2 reason 含 `lt`（文本过短规则 `lz_text_lt5`/`anon_text_lt2`）
   **且** 汉化后含连续中文段含**非纹理字**（`any(c not in _ART_TEXTS for c in seg)`）。
   `no_dialogue`（无对话判定）纹理行永不兜底——`no_dialogue` 是 1025 行 art 的主 reason，lt 只有 12+3+2 行，
   reason 是干净区分信号（**比中文正则可靠得多**）。

## 新发现（v2 kind=text 整行误伤）
- `来了哦！`（人物脸+台词）/`冠军的那个`（画面+台词）被 v2 整行判 text（reason=`lz_dotted`）→ 整行嵌字毁画面。
- 修复：**行内 art 字符占比 >30% 时只嵌台词子串**——`art = sum(c in ART_SYMS+ART_KATA+ART_HIRA+ART_KANJI)`，
  `art/len(non_space) > 0.3` → 用正则 `[^\s{artset}]{2,}` 找非艺术连续段嵌字（注意 art 字符集 join 后要 re.escape）。
- 全章 514 个 v2 text 行仅 1 行受影响（2053），修复后正确只嵌"来了哦！"。

## 最终判定逻辑（v2_text_spans 收敛版）
```
1. v2 有 segments → 只取 kind=text 且 conf≥0.7 的段（mixed 行）
2. v2 整行 kind=text → art 占比>30% 则只嵌非艺术连续段；否则整行嵌字（纯文本行无 segments）
3. v2 kind=art/mixed → reason 含 'lt' 且汉化含语义中文 → 整行嵌字；否则不嵌（no_dialogue 纹理安全）
```

## 验证结果（ad-hoc ALL PASS）
- 识别 8 例全对：纹理（八_人/二二二二）0 段；短台词（３．奈良/岩手/松実宥）1 段；纯文本（红豆串）整行；
  画面+台词（来了哦！）只嵌子串；【现状】标签 1 段。
- 36/90 块有嵌字像素变化（楼主楼）；纯文本块宽 612 保持（用户楼零回归）；PNG-8 关键色 0 缺失。
- 嵌字文字 8 倍放大确认：清晰、无重影、无裁切。

## ⚠️ 待决策：字号策略（用户尚未拍板）
- **楼主楼 AA 画面块 fs=16（MIN_FS 卡底）**，嵌字 16→18 视觉增量很弱；用户楼行级加大基线 fs≈19-22
  （+2 后 21-24px）→ 楼主楼嵌字文字（18px）比用户楼明显小一号，全书台词字号不统一。
- 选项：A. 保底 `max(fs+2, 21)` 与用户楼拉齐（推荐）；B. 严格 +2；C. 用户先看手机实际效果再定（已上传单章）。
- 相关：用户原话"文字+2和用户内容一致"——需澄清"一致"指加大幅度还是最终字号。

## ✅ 字号策略已定（第二轮，用户拍板"先看手机再定"→ 图宽自适应）
- 用户实测：**0002 图宽575 / 0009 图宽693 字大小合适，0001 图宽834 字显小**——
  "需要根据宽度判断字体大小（0001图文字先再+1看看）"。
- 实现：嵌字字号 `fs_embed = fs + 2 + (1 if 图宽≥800 else 0)`（图宽指 block_layout 预估 img_w，
  非 crop 后宽；0001 img_w=811 → 19px）。**不是**用户楼那种按文字行宽铺满的自适应——那是另一个思路，未采用。

## 第二轮实现记录（2026-08-14 用户 5 项反馈全部修复并验证）

### 用户反馈 → 根因 → 修复（每条都是坑）

   不含 `ヽ_ノ_`，`ノ` 在 ART_KATA 但 `_`/`ヽ` 不在 → 29% 漏判）→ 只嵌台词子串。

### v2_text_spans 最终判定逻辑（第二轮收敛版）
```
1. v2 有 segments → text 段 conf≥0.5 且段内含中文才嵌（0.7→0.5：mixed 行真台词段常 0.55）；
   一个有效段都没有 → 落兜底2（segments 分支不再无条件 return）
2. v2 整行 kind=text → art 占比>25% 则只嵌非艺术连续段（含 ヽ_ノー=― 补充字符）；否则整行嵌字
3. v2 kind=art/mixed → reason 含 'lt' 且汉化含语义中文 → 整行嵌字（兜底1）
4. mixed 且以上都没命中 → 兜底2：中文段向前后扩边界嵌字（0019 场景）
```
