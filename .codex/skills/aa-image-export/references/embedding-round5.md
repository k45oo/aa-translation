# 嵌字第五轮修复（2026-08-14 用户 2 项反馈：右缘被裁 + 空格压缩）

> 承接 embedding-round4.md。第五轮用户手机实测反馈 2 类问题，根因是**嵌字膨胀未计入图宽预算**，
> ad-hoc 验证 7 项 ALL PASS。

## 用户反馈 → 根因 → 修复

1. **0072 \"么？】\"还是看不到**（第四轮合并已生效但右缘仍被裁）
   → 根因：嵌字文字 SimHei fs_embed(19px) 比原文 PGothic(16px) 宽。实测原文段 x=413..804（宽 391px），
   嵌字后 568px → 右缘 x=981 **超出实际图宽 868 → \"么？】\"画在画布外被裁**。
   修复（两层）：
   - **block_layout 加 `embed_v2` 参数**：freeze_post 且该行有嵌字段时，按嵌字字号
     （`fs+2`，宽图≥800 再加 1）预估宽度——`f2 = max(f2, min(fs+2+(1 if width>=800 else 0), TEXT_MAX_FS))`。
     main 三处 block_layout 调用都传 `embed_v2=embed_v2`。实测 img_w 804→901，右缘文字完整（x=839/873）。
   ⚠️ **嵌字膨胀必须计入图宽预算**：SimHei fs+2 比 PGothic fs 宽 ~45%（391→568px），
   不预留则行尾台词（么？】/最右字）出画布被裁——症状是\"某字看不到\"但 spans 明明完整。

2. **正文多余空格要压缩**（\"亚鲁欧　　　　　现在在\"中间 6 个 U+3000）
   → 用户：正文连续空格可压缩（至少保留 1 个），其他类似正文间空格同理。
   修复：嵌字逐字符绘制时**连续空格只推进一次宽度**（`prev_blank` 标志）：
   ```python
   cx = x0
   prev_blank = False
   for ch in txt0:
       if ch.isspace():
           if not prev_blank:
               cx += pick(ch, fs_embed, True)[1]   # 连续空格只算一个宽
           prev_blank = True
           continue
       prev_blank = False
       # ... 绘制字符
   ```
   ⚠️ **行首空格不能压**（保持原文位置防右偏，0011 教训）；只压正文中间连续空格。
   实测 `【印象中...么？】` 513→437px（省 76px = 6 个压缩空格）。

## 排查陷阱（本轮回溯耗时的教训）

- **文件行号定位时 `[:N]` 截断会误导**：0072 的 txt 行 2515 是\"画面 + 行尾台词\"混合行
  （`|:| || 人　レ ... |: |　　【印象中...现在在做什么？】`），打印 `[:45]` 只看到画面部分，
  一度误判\"该行无台词\"。**用 grep 精确行号 + 打印行尾（`t.rstrip()[-40:]`）确认台词位置**。
- **验证嵌字是否渲染出来**：扫描全图 ink 行簇可能把嵌字文字行与其他行分开（不同 y 簇），
  漏看最右缘——应直接扫目标 y 区间的 ink x 范围对比图宽。

## 第五轮验证（ad-hoc ALL PASS，7 项）

- 0072 嵌字文字右缘 x=839/873（>图宽 90%，\"么？】\"完整可见）
- 空格压缩 513→437px（省 76px）
- 0011 不右偏 x=(198,510) 与 v8 一致；画面行（从劜/八芹坏）0 段
- 纯文本 612 / PNG-8 关键色 0 回归

## 核心教训

- **\"某字看不到\"优先查右缘是否出画布**（嵌字膨胀 vs 图宽预算），不是 spans 缺段。
- **正文空格压缩 = 防溢出 + 省空间**双收益；行首空格保持原文位置是底线。
- 嵌字 5 轮迭代至此：识别（no_dialogue 过滤/尾缀并入/缺口补齐）→ 绘制（逐字符 pick/空格跳过）
  → 布局（预算放大/空格压缩）三层都已踩过坑，改动任一层都要回归其他层（0011 右偏是布局回归的哨兵）。
