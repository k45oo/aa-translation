# 字体与对齐调查(2026-08-09,さーきー 第1话渲染调试实录)

## 结论链(为什么最终用 PGothic+SimSun 回退)
用户反馈顺序:①图片错位 ②部分中文变"口" → 排查发现:
- MS Gothic 缺简体字形(JIS 无 说们这红饭钱车东长门问等)→ "口"
- SimSun 简体全,但半角片假名全宽 → 错位
- Sarasa Mono SC 完美等宽但宽度语义≠MS PGothic → 用户仍说错位
- 最终:浏览器实测交付 HTML 字体栈 → **MS PGothic 是比例字体**,HTML 里 AA 就是这个比例效果,用户视为"正常" → 图片须复刻

MS Gothic(UPM=256,完美等宽):全部字符恰好 128(1格)或 256(2格);`¨′×°…`=256(2格)、`—`=128(1格)。

## 浏览器测量方法(Edge headless + CDP + node)
```js
const ctx = document.createElement('canvas').getContext('2d');
ctx.font = '15px "ＭＳ Ｐゴシック","MS PGothic",...,"SimSun",monospace';
ctx.measureText(ch).width   // DirectWrite 同引擎,与 DOM 渲染一致
```
node 原生 WebSocket 连 CDP(端口 9222),`Runtime.evaluate` + `returnByValue`。

## fontTools cmap 生成(fonts/msgothic_cmap.json)
```python
from fontTools.ttLib import TTCollection
import json
tc = TTCollection(r'C:\Windows\Fonts\msgothic.ttc')
pg = tc.fonts[2]   # 0=MS Gothic, 1=MS UI Gothic, 2=MS PGothic
json.dump(sorted(pg.getBestCmap().keys()), open(r'<repo>\fonts\msgothic_cmap.json', 'w'))
```
用项目 .venv 的 python(已装 fonttools/py7zr):`uv pip install --python .venv/Scripts/python.exe fonttools py7zr`

## 缺字检测陷阱
- `ImageFont.getlength(缺字)` 返回 .notdef advance(通常=1em)→ 宽度扫描全部"正常",测不出
- `getmask(c).getbbox()` 对缺字返回非 None(有 .notdef 轮廓),空格返回 None——无法区分
- 唯一可靠:fontTools `getBestCmap()` 码位集合判定

## 验证脚本要点(ad-hoc,用完即删)
1. hmtx 断言: 全语料字符 `round(PIL_getlength/半角)*半角 == hmtx advance`(容差 2, UPM 换算)
2. 浏览器对照: 22 个代表字符(比例字符+简体回退),PIL 30px vs 浏览器 15px×2,容差 2.5px;累计漂移 <3px
3. 端到端: `--out <临时目录>` 跑命令行,断言图数(第1话=9)/尺寸/红绿像素
4. 陷阱: monkeypatch `reg.get` 的 lambda 必须 `dict(_c)` 闭包固定 cfg,否则第二次生成用第一次的配置(saki_fc2 被 saki 配置污染,章节数错乱)
