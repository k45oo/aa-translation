# 嵌字第六轮修复（2026-08-14 用户 2 项反馈：AA 括号被放大 + 行首空格被误压缩）

> 承接 embedding-round5.md。第六轮用户手机实测反馈 2 类问题，根因是**识别边界漏了 AA 装饰字符** +
> **空格压缩策略一刀切**，ad-hoc 验证 10 项 ALL PASS。

## 用户反馈 → 根因 → 修复

1. **64 图 `{　　　　　　　　　　　　}　　 　 　 【现状】` 左侧括号对被放大**
   → 根因两层：
   - **`{` `}` 不在 ART_SYMS**（艺术符号集只覆盖线条/框线类）→ 嵌字 spans 把它们当台词纳入
   - **兜底1（lt 短台词）用 `(lead, len(txt))` 整行嵌字**——`{　...　}` 装饰括号在行首，
     整行嵌字 = 放大括号 + 压缩括号内空格
   - 修复：
     - **ART_SYMS 补 `{}（）()`**（AA 装饰括号；⚠️ 全角引号 `『』「」【】` 不能加，
       它们是台词标点）
     - **兜底1 改为中文段定位**（与兜底2 同款 `s0 向前/向后扩到非空白非 ART_SYMS`）——
       不再整行嵌。实测 spans=(12,37)→(33,37)，只嵌 `【现状】`
   - ⚠️ **教训：识别边界的扩展逻辑（向前/向后扩）必须把 ART_SYMS 当硬边界**；
     ART_SYMS 覆盖不全（缺 `{}（）()`）时，画面装饰会被当台词整段放大

2. **行首空格被误压缩**（0001 图 `・以《` 介绍内容前导 9 空格被压成 1 个 → 正文左移）
   → 根因：round5 的连续空格压缩 `prev_blank` 标志**对行首空格也生效**——段首连续空格只推进一次。
   - 修复：空格策略分两段（`seen_nonblank` 标志）：
     ```python
     cx = x0
     prev_blank = False
     seen_nonblank = False
     for ch in txt0:
         if ch.isspace():
             if seen_nonblank:            # 正文中间: 压缩(连续组只推一次)
                 if not prev_blank:
                     cx += pick(ch, fs_embed, True)[1]
             else:                         # 行首空格: 每个都推进(不压缩,防左移)
                 cx += pick(ch, fs_embed, True)[1]
             prev_blank = True
             continue
         prev_blank = False
         seen_nonblank = True
         # ... 绘制字符
     ```
   - ⚠️ **教训：空格压缩只对"正文中间"（第一个非空字符之后）生效**；行首空格是 AA 对齐
     的一部分，压缩会让整行文字左移（用户视为"正文错位"）。round5 的压缩实现少了
     `seen_nonblank` 判定，006 轮补上。

## 核心教训

- **ART_SYMS 是嵌字识别的硬边界**：补字符要想到 AA 装饰类（括号/引号/框线），
  但**台词标点（『』「」【】）绝不能加进 ART_SYMS**——加了会把台词头尾当画面跳过。
- **空格压缩必须区分行首 vs 正文中间**：行首空格=对齐语义（不压），正文空格=可压缩冗余。
- 嵌字 6 轮迭代完整谱系：
  - 识别：no_dialogue 过滤 → 尾缀并入（-saki-】）→ 中文缺口补齐（"个"字）→ ART_SYMS 补括号
  - 绘制：逐字符 pick（SimHei 缺字回退）→ 逐字符 x 定位（防右偏）
  - 布局：预算放大（embed_v2）→ 空格压缩（行首保留/正文压缩）
