# 反哺原翻译流程分析（2026-08-18 grilling）

> 本轮图片版视觉辅助优化收官后，讨论哪些发现可反哺原翻译管线（aa-manga-translation）。

## 用户报告的漏译类型
"1句完整话被分2段翻译（或1段翻译1段漏译）"——用户想讨论系统检测/修复方案。

## 调查数据
- 管线 `translate_lines_mixed`（aa_translate.py:759）**按 segments 分段独立翻译**（每段单独送模型）
- 14524 行 mixed（含 ≥2 text 段）中 **9570 行（66%）有"相邻 text 段间距≤1"**（同一句话被 v2 segments 切成多段）
- 抽样 55 行：**绝大多数是 v2 segments 误标**——画面字符（Τ/∨/ヽ/z/ミ/i/l/斗/示/芋/米）被误标为 text 段；
  真正台词切分（`不行不行`+`r`、`来，yello`+`w！`）极少（55 行里仅 1-2 例）

## 结论
1. **段合并翻译方案不成立**——9570 行里 99% 是画面误标段，合并只会把画面并到一起，无益
2. "1句分2段翻译/1段漏译"的真正根源 = **v2 segments 把画面字符误标 text**，模型把画面字符当台词翻/漏翻
3. **正解反哺路径**：用视觉判定（v3）校准 v2 segments——v3=art 的行其 text 段标记为"画面"（不译不嵌）

## 视觉校准的量化价值
1302 行 v3=art（视觉确认画面）中：
- v2 kind=art：951 行（原流程已正确跳过）✓
- **v2 kind=mixed：288 行**（原流程送模型译台词部分——浪费 token + 可能误翻）
- **v2 kind=text：63 行**（原流程整行送模型——最危险）
- 合计 **351 行（27%）在原翻译流程被判"有文本"送过模型**——视觉校准可避免这些

## 教训（方法论）
用户报告"漏译/误嵌"类问题时，**先查数据形态再定方案**：
- 间距≤1 的"切分"绝大多数是画面误标，不是真台词切分
- 拍脑袋做"段合并"会白做（本轮先抽样 55 行验证后才否定该方案）
- 量化（14524/9570/351 行）支撑决策，不凭感觉
