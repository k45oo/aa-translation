# 术语表应用与并行 git 的坑（2026-08-14 实战）

## 1. apply_glossary_chapter 帖头污染已修复（_SKIP_RE 加帖头模式）

- **问题**：术语替换曾把帖头作者名也替换——「本棚のやる夫さん」→「本棚の亚鲁欧さん」。`logic.is_skip_line` 原来只跳 `#`/`=====`（`_SKIP_RE = re.compile(r"^(#|=====)")`），帖头行（`NNN ： 名前 ： 日期 ID:...`）不跳过。
- **修复**：`_SKIP_RE = re.compile(r"^(#|=====|\d{1,4}\s*：)")`（帖头特征 = 1-4 位数字 + 全角冒号开头）。`is_skip_line` 只有 2 个调用点（267 行单行矫正宽度校验跳过、340 行 apply_glossary_chapter 术语替换跳过），两处都受益。
- **验证**：dry-run 时先断言「替换行无帖头」——实例：73 行替换中 61 行是帖头污染，修复后 12 行全为正文。`test_aaweb.py` 37 用例全过无回归。
- 帖头正则风险低：正文台词不以「数字+全角冒号」开头（骰子行为半角 `:` 或不同格式）。

## 2. 术语替换对（glossary 二元组）设计原则——短词子串误伤

子串 replace 的替换对（`[日文, 中文]`），日文侧太短会误伤更长词：

| 危险对 | 误伤实例 | 结论 |
|---|---|---|
| `ドラ→宝牌` | ドラマ/ドラゴン/ドランカー | **禁用** |
| `カン→杠` | カンジ(感じ)/カンケイ(関係) | **禁用** |
| `一発` | 「一発くるでー」替换后留「くるでー」残留假名 | **禁用** |
| `やんねぇ` | 角色名「やんねぇ香」被破坏成「不做吗香」 | **禁用** |
| `ロン/ポン/チー` | 麻将语境下安全（コロン/マロン 类词在 AA 语料罕见） | 可用 |
| 长词（草生える/ワロタ/乙でした/リーチ/国士無双） | 无 | 可用 |

**设计规则**：
1. 词长 ≥2 音节，且确认目标语料中无更长词以该串开头
2. 2ch 网络语用**完整词形**（草生える/ワロタ/乙でした），单字（草/乙）禁用
3. 新增对后必跑 dry-run 替换验证：「替换行无残留假名、无帖头」
4. 日文侧重复会被 `validate_glossary` 拒（保存时已防呆）

2026-08-14 实际新增 30 对（2ch 网络语 13 + 麻将术语 17）到全局 glossary.json（8→38 条），全部避开上述危险对。

## 3. 并行会话 `git add -A` 会把工作区未提交修改带进它的 commit（629bf66 事故）

- **场景**：另一个 TUI 窗口跑批次收尾 `git add -A && git commit` 时，把本会话刚写入 glossary.json 的 30 条术语对**一起提交**——commit message 是它的「B2 残留清零」，但文件内容含我的修改。
- **症状**：自己 `git add glossary.json && commit` 显示「1 file changed」（只有我的代码文件），`git log -- <文件>` 找不到对应提交，但 `git status` 显示文件无修改、`git show HEAD:<文件>` 内容已是新版本。
- **判定**：`git show <并行提交>:<文件>` 对比内容确认无丢失即可，**别重复提交/回退**。
- **防御**：多窗口并行 git 操作时，写数据文件后尽快提交，或先 `git stash` 隔离工作区修改。
