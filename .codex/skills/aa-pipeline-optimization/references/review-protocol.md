# AA 管线审阅协议

> 2026-08-10 确立于 M0–M5 里程碑审阅实践。以下规则已整合到 SKILL.md，本文档为细则参考。

## 审阅报告规范

每次里程碑完成或进度审阅后，**必须产出审阅报告**：

- **路径**：`<repo>\doc\审阅报告_<日期>_<主题>.md`（不进 temp/，git-tracked）
- **固定章节顺序**：
  1. 总体评估（1-2 句结论）
  2. 前置风险核销表 — 逐项核对上次审阅的「下次审阅确认点」
  3. 交付物核实 — 行数/功能/测试通过率/交叉验证证据
  4. 数据可信度证据 — 交叉验证、抽检结果、独立工具互证
  5. 风险清单 — 新发现 + 遗留未解，按优先级
  6. 下一步行动 — 按优先级 + 预估工时
  7. **下次审阅确认点清单**（强制章节，bullet checklist）
- 下次审阅时必须先核对上次的确认点清单，逐项标注状态

## Flag 滞留检测

- 审计命令：`grep -rn "os.environ.get" scripts/` 找所有 flag 读取点
- 已验证但未翻的 flag 按收益排序作为最高优先级建议
- 典型历史案例：M2（2.53x 加速）、M4a（-40% token）全部滞留 0，错失已验证收益

## 交叉验证证据

- 独立工具对同一问题收敛于相同结论 > 单一测试通过
- 数据级吻合（如 metrics_report total vs《统计对比报告》）是最硬的证据
- 历史案例：quality_gate G4 发现的 5 处真漏译精确匹配 M4b `is_copy_failure` 拦截目标

## 闸门曝光 vs 闸门引入

- 质量闸门首次上线时，会系统暴露之前不可见的历史缺陷
- 审阅报告必须区分「闸门引入的新问题」vs「闸门曝光的旧债」
- 验证闸门无误报：抽检结果与底层函数一致（如 25/25 宽度与 disp_width 全吻合）

## 审阅检查清单

每次审阅结束前确认：
- [ ] 上次审阅的「下次审阅确认点」已全部核对并标注状态
- [ ] 所有 flag 状态已审计，滞留 flag 已在建议中列出
- [ ] 交叉验证证据已在报告中呈现（如有）
- [ ] 新发现的缺陷已区分「新引入」vs「历史债曝光」
- [ ] 报告已写入 `doc/审阅报告_<日期>_<主题>.md`
- [ ] EXPERIMENTS.md 的里程碑进度和 flag 状态表已同步更新
