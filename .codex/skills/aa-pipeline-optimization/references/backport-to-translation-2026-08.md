# 图片嵌字优化反哺翻译流程（2026-08-18 会话详情）

> grilling 定稿 + 三批实现。方案：`doc/图片嵌字反哺翻译流程方案_2026-08-18.md`；实验：`doc/反哺实验记录_2026-08-18.md`。本项目内提交：8083720（方案+实验文档）、5b717cd（第一批⑥⑨）、ec9ab24（第二批②⑤+⑦评估）。

## 核心发现：吞字漏译根因

用户反馈"1句完整话被分2段翻译（或1段翻译1段漏译）"，案例：
- `entry_9556` 行1803：`いいお出かけ日和だお` → "适合出门　　日呢"（**"日和"吞字** + 空格补宽）
- `entry_9557` 行2889：`これからは日曜日に来てくれ` → "以后就　　　　日曜日"

**排查结论**：不是段切分（v2 segments 里真台词段完整未切、conf=None 整段）——是**模型删实词 + pad_segment 用 U+3000 补宽**，整行宽校验（`disp_width(cand) != disp_width(line)`）被画面段+台词段合计宽度掩盖。汉字级吞字（日和→日）假名残留检测也抓不到。**只有语义对照能发现**。

**排查方法**：先复现案例（原文/汉化/v2 segments 三面对照）→ 确认段完整 → 用 disp_width 对比原文段宽 vs 译文段宽（32 vs 28）→ 定位"宽度对但语义丢"。

## 反哺点实现细节

### ⑥ SYSTEM_MIXED 提示词优化（已实现，aa_translate.py）
旧版第 2 条"不要添加空格"被模型无视（删字后补空格）。新版：
- "**必须完整表达原文语义，不得省略任何实词**（名词/动词/形容词/副词一个都不能丢；宁可译文略长，也不要删字凑短）"
- "**绝对不要用空格填充宽度**"
- "但**不得因宽度限制而删语义**"
- few-shot 3 例：完整译出（`いいお出かけ日和だお`→`真是出门的好日子啊`）/ 角色名保留（やる夫）/ 纯装饰照抄（ヽ）
实测：同输入旧提示词偶发吞字（"真是适合出门的好天气呢"曾正确但"适合出门　　日呢"曾吞字），新提示词稳定完整译出。

### ⑨ is_translatable reason 过滤（已实现，防御性）
`load_meta_0based` 返回 `{idx: (kind, reason)}` 元组（兼容旧 kind-only 字符串——`is_translatable` 内 `isinstance(entry, tuple)` 分支）。mixed 分支：`'no_dialogue' in reason → return False`。
**实测全库 0 行触发**——v2 分类器 no_dialogue 行 kind 本就是 art（非 mixed）。结论：⑨ 是防御代码，画面误标治本靠 ⑤。

### ② 段级宽度校验（已实现，translate_lines_mixed）
在 `trans[si] = t` 前加：
```python
seg_has_text = (real_kana or any('\u4e00' <= c <= '\u9fff' for c in orig_seg))
if seg_has_text:
    if disp_width(t) > disp_width(orig_seg):   # 超宽 → seg_wide
        ok = False; reason = f'seg_wide seg{si}'; break
    if disp_width(orig_seg) - disp_width(t) > 4:  # 吞字嫌疑(>2全角字) → seg_shrink
        ok = False; reason = f'seg_shrink seg{si}'; break
```
失败 → 整行重译（3 轮）→ 落 review。注意：**失败重译粒度是整行**（jobs 按行分组发），"只重译失败段"需改 jobs 生成，收益小已跳过。

### ⑤ v3 回写 v2（已实现，scripts/tools/v3_backport_v2.py）
- v3=art 的行 → segments 里 `kind=='text' and conf>=0.65` 的段：`conf=0.0` + `kind='art'`
- `_confident_text_segs` 要求 conf≥0.65 → 回写后不进翻译/嵌字
- **73 章实测 255 行 / 367 段**修正（这些画面段之前全被送模型/放大）
- `--dry-run` 先预览再写；v3=text 行不动（视觉确认台词）；无 v3 判定行不动
- 验证：行3107（4 画面段 `《`/`汽`/`イ忙汽`）回写后 `_confident_text_segs` 空

### ⑦ 段合并（评估后放弃）
回写后仍有 2607 行"相邻 text 段"（间距≤1），抽样显示**绝大多数是并排独立台词**：
- `'照　|我最好的朋友！'` = 人物名 + 台词（独立内容）
- `'哎呀—　|真受欢迎啊！'` = 并列短语
- 真切碎（`'来，yello'+'w！'` 一词切开）是极少数
**合并会误合并并排台词破坏语义** → 不做。⑥ few-shot 已让模型自主判断相邻段关系。

## 关键认知

1. **规则校验（宽度/残留）抓不到语义级问题**——"日和"吞字后宽度被 pad 补对、无假名残留，规则全放行。最后防线是视觉复核或模型自检（提示词语义约束）。
2. **视觉判定精度取决于提示词口径非模型强弱**：全图扫描台词行 → gemini/Qwen32B/M3 全误判轮廓行；红框标注+只判存疑行 → 4 模型判定一致。翻译提示词同理：约束要具体（"不得省略实词"）且有示例。
3. **先数据后方案**：⑦ 段合并差点实施，抽样 2607 行后确认是并排台词而非切碎，避免误伤。任何"合并/过滤"类改动先抽样看真实形态。
4. **grilling 定稿流程**：反哺类跨系统改进先逐项确认（一次一问附推荐答案）→ 方案文档 → 实验记录文档 → 提交 git → 分批复实现。
