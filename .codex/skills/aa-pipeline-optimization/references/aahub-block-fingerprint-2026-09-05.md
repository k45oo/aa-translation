# AAHub 块级指纹匹配：跨角色区分实测定案（2026-09-05）

**关联（均为历史，2026-10-10 已废）**：`aa-pipeline-optimization` SKILL 的「AAHub 行数据库辅助分类/分段」节；原 `doc/TODO/` 已随方案判不可行删除（本文仅留档）。

**背景**：块级匹配可行，但此前「跨角色区分」失败（字符频次 top2-9 全紲星あかり）——文档曾写在「方向重定待定」。本参考记录了 2026-09-05 在真实库 `temp/aahub_4role/aahub.db`（4 角色 3174 块）+ 正文岛风块（`entry_20990.txt` 行 2406-2434，29 行）上跑基准后的定案。

## 核心结论

1. **「跨角色是伪命题」判断正确，但死因判错了**：不是「内容指纹区分不了角色」，而是 **char-freq 是**无序袋（orderless bag），**丢了空间位置信息**。换成**位置敏感的内容直方图（Spatial Pyramid Matching, SPM）**，跨角色分得开。
2. **角色身份由「形状/梯度」承载，姿势身份由「内容分布」承载**——两条判别轴不同，单一特征无法同时满足两个粒度。
3. **正文块 ⊂ DB 块**（29 行 ⊂ 45 行，正文只贴了立绘一部分）——这是**包含/子序列定位**问题，不是整块对整块。用**滑动窗口**匹配比整块匹配更强（0.759→0.836）。

## 为什么 dHash 角色对但姿势错、密度网格跨角色塌

- **dHash（二进制梯度）= 形状**：不同动漫少女的轮廓/发型/身形不同 → 梯度不同 → 角色分得干净（top8 全岛风）。但它是全局形状哈希，不区分块内的内容分布 → 姿势分不开。
- **密度网格丢内容**：只数「格子里有没有字」，丢了字符类别 → 跨角色也塌（不同角色的 2D 网格密度分布太接近）。
- **char-freq 恰中**：同角色内它强（blk64 0.990 vs 同角色他块 0.500），但 top2-9 全紲星 0.972-0.960，排第几不可信。

## 推荐架构（角色闸门 + SPM + 细验证）

```
阶段0 角色闸门：本章台词/素材统计已有角色集，或 dHash 粗桶，缩到候选角色
阶段1 粗召回：候选角色内，用字符类别 SPM 直方图对全块点积（纳秒级）拉 top-K
阶段2 细验证：只对 top-K 候选，滑动窗口行范围对齐 + 窗口内行级 difflib，锁精确行号
```

- 用 SPM 做又快又准的粗召回 + 只在 top-K 跑昂贵的行级对齐（替代当前全章 3207 行 × 30 候选 difflib 的 806s）。
- **角色闸门消除跨角色歧义**（两个粒度分开处理）；**滑动窗口处理子集结构**；SPM 做排序。

### 两级匹配取代逐窗 sph() —— 「数据量暴涨」的解药

`match_block` = 粗召回（整块 SPM 余弦 top-`coarse_n` 默认 10）→ 行级对齐（`_best_offset`，单行 7 维类别直方图 O(L*H) 点积定位 offset）。@粗召回固定 top-N = **不管库多大/角色多少只对 N 个块细化**，正是用户「角色多了数据量暴涨」否决 difflib 的根因对策。全章 entry_30179（3207 行）匹配 ~18s（旧 806s，~1/45）。

### difflib-free mixed 文本识别（用户问「不用 difflib 能否识别 mixed 行文本」→ 能）

命中块后，逐行取 DB art 右边界（`rstrip('\u3000 ')` 的 disp_width），正文越过边界的右内容 = 候选台词。纯列几何 O(1)/行。入口20990 已知两漏判行 L2422「ま、まさか！」/L2424「貴方が伝説の！」都命中（块命中正确时）。*机制成立，但精度受块命中精度制约（0.68）。*

### 越界串 is_text 判别器 = 全角假名 art 描边黑名单（管线级缺陷修复）

**发现的管线级缺陷**：`aa_translate.is_text_line` / `line_classify_v2._has_dialogue` 都用 `KANA_RE.search`（含全角假名），遇到「全角假名当绘画笔画」的越界串（`ﾆﾆ|ニニニ|_|＿＿…`、`／／＿|＿`）都返回 True——`ﾆ/ニ/ー` 是 AA 描边非台词。**不能自造 `kana_runs` 正则**（AA art 常用假名/汉字作笔画 ﾍ≦∨/一丨，也会误判）。

修复 = `BlockMatcher` 越界串专用判别器（管线 is_text_line 是整行语义，越界子串是不同分布，不能直接复用）：
- **`overhang_is_text`**（词规则）：连续 假名|汉字 run≥2 且 **`distinct_kana≥3`**（NFKC 归一化半/全角 `ﾆ`/`ニ`）→ 真台词
- **`max_repeat_run≥4`**（单字符重复边界线 `ﾆﾆﾆﾆ`/`ﾞﾞﾞﾞ`/`-=-`）→ art
- **`art_frac>0.62`**（图形/边界字符为主）→ art；⚠️ **必须只计非假名且非汉字**（旧版把汉字当 art 会误杀汉字台词「貴方が伝説の！」——岛风 L2424 回归教训）

实测 entry_9184：art_frac 守卫旧版 = 26 真台词误杀 + 18 art 残留漏放；词规则新版 = 60 输出中 **55 确认真台词**、仅 5 待复查，**岛风黄金两行回归全命中零误标**。入口 20990 黄金块在修复前后 is_text 都恰好 2 条（零 FP）。

### 关键发现①：按 line_meta kind 切段是鸡生蛋（碎段漏匹配）

line_meta_v2 把立绘行误标成 text/mixed 时，那些行**不会进入 art/mixed 段** → 块匹配根本看不到它们。且立绘被切碎（51-52 两行段、58 单行段）时 `<3 行`直接 None。**修法：段定义放宽 = 连续非空行（跳过帖头/`#`/`=====`）整段送匹配**，不依赖 line_meta kind → entry_9184 104 段**全部命中 0 未命中**（キャル/鑢七実/夢見りあむ 三角色立绘 score 0.93-1.0）。块匹配辅助分类必须自切宽段，勿复用 meta 的碎 kind。

### 关键发现②：工作台行类型 ≠ gold（「误标」指什么）

`gold_dialogue/*.json` = 稀疏人工二值修正 `{1-based行号: bool}`，true=该行确有台词(漏判)、false=纯AA(行分类器误标)。但工作台**行类型标签**（text/mixed/aa 左侧标签）由 `wtype = line_meta_overrides > line_meta_v2 > line_type_of` 决定；**gold 只改 `dlg`（台词高亮/是否算台词），不改类型标签**。用户报「49-70 仍误标」= 行类型标签还显示 text/mixed——修它要**重生成 line_meta_v2 或写 line_meta_overrides**，不是 gold。

### 关键发现③：overhang_is_text 最终形态（v3，尾部台词尾巴）

演进：v1 art_frac>0.55（汉字算 art，误杀汉字台词）→ v2 词规则（整串判，被 art 前缀稀释漏 `ﾋｯ！？`/`今度は誰だ！`）→ **v3 = 从右往左取「假名/汉字 + 台词标点(。．！？…〜ｯッ)」连续区为 tail**（art 前缀碎片在前不干扰）。判据顺序：
1. 整串连续假名/汉字 run≥2 且 distinct_kana≥3 → 真台词
2. tail 单字重复≥3 且 dk≤1（`二二二`/`一一一`）→ art（边界线）
3. tail 纯标点**且 len≥2**（`……。`/`！？`；**单 `!`/`丶` 是碎片不算**）→ 真台词
4. tail dk≥2 且无单字重复（`ﾋｯ`/`ｸﾞｯ`）→ 真台词
5. tail 含汉字且非 art 笔画字（`二一三丨丶丿` 排除）→ 真台词

12 用例回归全过（L66 `……。`/L644 `ﾋｯ！？`/L646 汉字台词/岛风 L2422/2424 = 真台词；L27/L35/L487/L61/L534/L937/L1228 = art）。`art_frac` 只计图形字符（**汉字/假名都算文本**，旧版把汉字当 art 误杀 L2424）。**管线级 `is_text_line`/`_has_dialogue` 对全角假名描边误标是真实缺陷**，但越界子串判定不能复用它们——用本判别器。
