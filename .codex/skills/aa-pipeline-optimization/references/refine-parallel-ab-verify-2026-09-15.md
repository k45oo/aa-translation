# 逐段模型调用 → 段级并发：改法与等价性验证（refine_aa 实证 2026-09-15）

**何时用**：管线某环节「比同类环节慢很多」时。先量化，别先怪模型。
配套工具：`python scripts/tools/ab_refine_verify.py`（等价性 / 真 API 计时）；方案与数据：`doc/方案归档/校对提速方案_2026-09-15.md`。

## 1. 量化手法（先测再改）

- **看单次请求规模**：`usage.jsonl` 里该 tag 的 prompt/completion 中位数。refine 实测 5789 次调用 prompt 中位 307tok、completion 中位 13tok，**`>600tok` 的调用 0 次** → 铁证「一次只发一行」，与模型无关。
- **看调用间隔**：refine 间隔中位 2.1~3.1s、`<0.5s` 占比 **0.0%**（纯串行排队）；同任务主翻译间隔中位 0.29~0.38s（`<0.5s` 占 60~68% = 章级 3 × 章内 8 并发）。**两者差一个数量级，差异在并发度与批大小。**
- **零 API 探针**：把 `_call_glm` 换成记录器（返回桩译文，保持代码路径可走通）跑真实章 → 得「次调用/章」与 **CPU 时间**。refine 实测 0.17~0.60s/章（<2%）⇒ 瓶颈 100% 网络往返。
- **单次调用延迟按端点实测**（同输入各 6 次）：官网 `deepseek-flash` 中位 0.77s vs `deepinfra GLM-5.3-Flash` 2.29s。小请求延迟几乎全是固定开销 → **换端点本身就是 3×**。
- 章级成本要用**产物自己的备份**当输入（refine 的 `work/backup_refine_aa_<ts>/` = 校对前状态），否则量到的是「已修好」的假象（首校 41 次/章 vs 已收敛 3.6 次/章）。

## 2. 改法：两段式（本地判定 / 并发调用）

- 行循环里只留**纯本地**判定（分段/分类/对齐/重建），把「发模型调用 → 校验 → 出 edit」抽成 job，用 `functools.partial` 收集，循环结束 `ThreadPoolExecutor(max_workers)` 并发跑，**结果按行号排序合并**（与串行同序）。
- **每条 job 恰产出一条 edit**；job 返回 `None` 时由调用方给回退 edit（落人工 / 超宽失败）。合并逻辑最简单，也不丢行。
- 分支差异（比较对象是 `s` 还是 `h`、是否剥 `^\d+\|`、是否二次精简重试、失败 reason 前缀）**用参数表达**，别合并成「近似统一」的实现——等价性就靠这些细节。
- 计数别在分支里 `+=1`：改成从最终 `edits` 派生（`act` + `ok` 过滤），少一处漂移点。
- 并发度给 env/TOML 开关（`AA_REFINE_WORKERS`，默认 8 = 主翻译章内并发），别写死。

## 3. 并发隔离清单（进程级全局会被多线程互串）

- 模块级全局提示段（refine 的 `_GLOSS_HINT`）→ 改**显式传参**。
- `os.environ["AA_USAGE_TAG"]` 这类「保存-设置-还原」hack → 给底层调用加 `tag=` 参数。
- usage 落盘：`append_usage` 的「查大小 → 滚动 → 写」必须加进程内 `Lock`（并发下否则双滚动/交错写坏行）。
- 已确认安全：`threading.local()` 的 usage 上下文、每次新建 opener 的 urllib 调用。

## 4. 等价性验证（必做，否则不敢上线）

- 输入用**备份**、两侧同源同起点；**永不写盘**（`do_write=False`，out_dir 指向备份目录）。
- 旧版取法：`git show <rev>:scripts/fix/refine_aa.py` → 临时文件 → `importlib` 加载成第二个模块，新旧并存。
  - **坑**：旧文件落在临时目录后，它自带的 `sys.path.insert(相对 __file__)` 会指错；把本仓 `scripts/`、`scripts/common/`、`scripts/fix/`、**`scripts/works/`**（registry 在这里；它不在这几个路径里，是靠别的模块 import 副作用才可解析）显式插到 `sys.path` 最前即可。
- **确定性 mock**（同 `(system, body)` → 同译文）替代真 API，排除模型抖动；**调用次数**也要比。
- 判定：`edits` 逐条（行号/动作/ok/reason/新行）+ `stats` + 调用数 全相同。
- **坑**：造「未翻译」夹具时 mock 别返回含**汉字**的日文——`翻訳` 等日文汉字落在 CJK 区间，会被判成「已翻译」；要用**纯假名**。
- 广度：换链/并发类改动至少覆盖 5~8 部作品 × 2 章（不同站点与画风差异大）。

## 5. 本次实测（refine_aa 2026-09-15，全部真 API）

| 改动 | 结果 |
|---|---|
| 换链 deepseek 主 → GLM 兜底 | 单次 2.29s→0.77s；A/B 两章 314.4s→81.3s（3.9×）/ 435.7s→102.5s（4.25×），**行集合完全一致** |
| 段级并发 8 | 123 调用章 86.5s→11.6s（7.4×）；141 调用章 95.2s→12.6s（7.5×）；16 并发 6.0s / 7.6s（12.5~14.5×） |
| 章级增量 ckpt（指纹=原文+汉化 sha1） | 重跑 **0 调用**；手改/重译/术语替换自动失效重校 |
| 单次预算 160s×3 → 25s×2、退避 ≤6s | 消 60~189s 单次长尾 |
| **合计** | 314.4s → 6.0s（**52×**）；等价性 8 作品 16 章逐条相同 |

## 6. 坑与约束

- 改**默认参数**要检查调用方是否显式传值：`_call_glm(..., timeout=160)` 的旧默认挡住新预算（单测逮住）→ 默认改 `0 → 取配置` 才生效。
- 跳过/短路分支必须**保留上游解析的日志契约**（如每章行首 `[entry_xxx]`，`translate_runner._refine_missing` 据此统计已校对章，缺了会被误判「未校对」）。
- 增量 ckpt 指纹必须含**产物本身**（汉化 txt），只含原文则手改/替换后不重校。
- 收益递减点：并发之后瓶颈转为**本地 CPU**（0.2~0.6s/章）→ 再上「批量合并请求」收益有限，别为它增加解析/回退复杂度。
- 并发上限要顾后端限流：本仓主翻译已是 章级 3 × 章内 8，refine 默认 8 与之同档；再高（16）实测更快但会推高 429 概率（有自动降级兜底）。
