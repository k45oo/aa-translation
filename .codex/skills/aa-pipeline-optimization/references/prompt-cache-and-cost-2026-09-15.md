# 前缀缓存命中与计费成本口径（AA 管线实证 2026-09-15）

**何时用**：要降 token/成本；或改模型链、改端点策略、改提示词结构前。配套工具：`scripts/tools/usage_stats.py --cost [--days N]`、`common/aa_cost.py`、`common/aa_prompt_prefix.py`；完整方案+批次见 `doc/方案归档/token成本优化方案_2026-09-15.md`。

## 1. 先立口径，再看折扣

- **token 数 ≠ 计费成本**。先记录 `cache_hit`（DeepSeek `prompt_cache_hit_tokens`；OpenAI 兼容 `prompt_tokens_details.cached_tokens`；Responses `input_tokens_details.cached_tokens`）——全库改写前完全没记录，所有「省 token」的推算都可能是省钱幻觉。
- **0 与「字段缺失」必须分开记**：前者=端点支持但未命中，后者=不提供。用 `_pick()` 链式取第一个非 None（不能用 `or`，0 会被吃掉）。
- **单价表缺失就别算钱**（只计 token），模型名含 `free` 记为 0 元；高峰倍率只对声明了 `peak` 的单价生效（DeepSeek 官网工作日 09-12/14-18 ×2，周末不翻倍）。
- 无 `cache_hit` 的历史记录按未命中价算 = **金额上界**，报表里必须标明，否则会拿上界当实际。

## 2. 实测结论（会缓存 / 不会缓存）

- 真实前缀 1696 字符 ≈ 1286 tok，同前缀连续调用：**只有官网 deepseek 命中**（384→1024/1024/1024 = 79.6%，64-tok 粒度）；
  deepinfra / runinfra 上的 GLM 系列 **0/0/0** → 网关侧不缓存，`pin` 到网关 = 白丢折扣。
- **并发不击穿缓存**（同前缀 8 并发首波 79.0%、预热后 88.9%）——调研里的 Anthropic 式预热要求**不适用于 DeepSeek**；别照搬厂商文档，实测。
- 健康态「每次调用都轮询端点」会把同一章打散到零缓存端点：**章内 pin + 跨章轮询**后 61.8% → 89.6%。
- 缓存生效后成本结构变为：命中输入 2% · **不可缓存的尾巴（正文+64-tok 残段）44%** · **输出 55%** → 重心从「瘦提示词」转向「少调用、少让模型复述」。

## 3. 让前缀真命中的工程条件

1. **拼在最前**：前缀缓存自第 0 token 起逐字节匹配。公共常量头拼在**所有** system 变体最前面，才能让不同任务类型互相命中（实测交错序列 0% → 55.8%）。
2. **按章锁定**：术语表/人物/章节简介只能按章过滤（章内字节恒定）；**按调用/按块动态筛选会让前缀每次唯一 = 击穿缓存**（实测成本反升 1.9×）。
3. **只在会缓存的后端拼**：`apply(system, backend)` 查 `[backend.X].cache`；网关不缓存时拼了只是白加 ~200 tok。
4. **前缀稳定性要跨进程验**：不同 `PYTHONHASHSEED` 各跑一次构建，sha1 必须一致（集合/字典迭代序泄漏 = 不同进程不同前缀）。
5. **常量改一次付一次代价**：改公共前缀文字 = 全库缓存失效一次；把它当 API 对待。

## 4. 坑（都是踩过的）

- **「自动选的后端」不等于「用户显式指定」**：runner 会自动设 `AA_BACKEND`，若把它当成显式选择而让 pin 让位，pin 会静默失效（实测跑成 4 端点轮询）。修法：自动值打 `AA_BACKEND_AUTO=1`。
- **按 `kind` 统计 ≠ 真实送模型行集**：判断「哪些行进了模型」一律用 `is_translatable(idx, line, meta)`，别用 `meta` 的 kind 直接过滤（会得出差 5 倍的结论）。
- **meta/segments 加载器的参数是 base 名**（`entry_<eid>`），传纯 eid 会静默返回 None → 整个分析退化成 is_text_line 回退。
- **小样本 A/B 会被输出方差淹没**：模型单次输出长度波动可达 3×，成本对比要用同批多轮或看输入侧分量。
- **段级协议不是万能**：把行转成「只发台词段」确实省输出，但项目里的段级残留校验把**艺术假名**排除在白名单外，全艺术假名的台词段会绕过校验（实测 10 行里 1 漏译 1 误译）→ 这类改动必须逐行查被接管的行，不能只看总成本。

## TM 整行复用（P3，2026-09-15）

- **key 是归一化源行**（去 U+3000/空格）。用 `line.strip()` 只有 **4.4%** 命中；归一化后 **21.1%** —— 行内填充差异是主要 miss 原因，别用原样字符串当 key。
- 命中即**零调用直出**：行不进模型，省的是全部输入+输出。实测 ハーレム大王国 3 章 A/B：¥0.1224 → **¥0.0993/章（−18.9%）**，69 行零调用。
- **必须四重护栏**（宽度放得下 / 无残留假名 / 术语表一致 / **art 列位一致**）：归一化 key 会命中「同内容不同填充」的行，只校字符序列会让 art 相对列位漂移（宽对框歪）。art 列位用项目自己的 `aa_translate._art_anchors()`，别另写字符集（自己写会误把假名当 art）。
- 宽度不同时本地 `pad_to_width` 补齐；补不动（译文比源宽）→ 丢弃交回模型。
- 定稿判据要**两条都给**：`work/refine_ckpt/<base>.json`（新流程）或该章出现在任一 `backup_refine_aa_*`（旧流程没 ckpt 但有写回备份）。只认 ckpt 会把 103/124 章排除在建表外。
- A/B 测量必须 `AA_TM_NO_BUILD=1`：否则 B 组开跑前会自动回填，把刚译好的目标章也收进表 → 自己命中自己，A/B 失真。
- 表在 `work/tm_<work>.json`（按章指纹增量）；`translate_runner` 翻译前自动回填（零 API），`AA_USE_TM=0` 关复用。

## Batch API：为什么最终不接（2026-09-15 评估）

别被「批量 5 折」吸引 —— **先算它会不会把已经吃到手的缓存折扣打掉**。

- 官网 DeepSeek **没有批量端点**（定价页功能表只有 Json/Tools/Responses/Anthropic API/FIM/视觉）。链上唯一有批量的 DeepInfra 只 **−20%**。
- 我们已在享受的折扣更大：官网**命中价 = 未命中的 2%** + **空闲时段 5 折**（高峰 = 工作日 9:00-12:00、14:00-18:00，其余含全周末都空闲）。
- 量化（近 24h 官网 translate+refine 实际量，命中 70% 口径）：现状 ¥4.74 / 去掉缓存再 8 折 ¥7.27（**+53%**）/ 换更便宜 GLM 估算 ¥5.15（+9%）。
- **持平门槛公式**：`(1−0.98h)p + 4o = 0.8p + 3.2o` → `h* = (0.2 + 0.8·o/p)/0.98`；本项目 o/p ≈ 0.11 → **h* ≈ 29%**。命中率高于 29% 就永远别接批量（我们 pin 后 65~81%）。
- **错峰先查，别想当然**：本项目 99.0% 的成本本来就落在空闲时段（自动化任务在傍晚/深夜跑）→ 错峰最多再省 0.5%，不构成工程理由。查法：按 `aa_cost.is_peak(ts)` 分桶。
- 重估触发：官网出批量端点 / 命中率长期 <30% / 要跑全库重校且用非链首模型。

## 段级（mixed）协议的三条铁律（2026-09-15 补校验时的实测教训）

1. **抠段判据必须要求"决定性证据"**：`含任一平假名` 是错的 —— `マっ！`（マ∈ART_KATA、っ∈ART_HIRA）、`ぅこ`（ぅ 小写）、`ヽへノ`、`ノし` 全是装饰，
   抠成段后模型会把它们当台词处理：原样照抄（漏译）或译成中文（破坏画面，实测 `ぅこ`→「呜」）。
   正确判据 = 含**非艺术、非小写**假名，或 ≥2 汉字且无相邻重复。改完抠段数 534→559（丢的全是 art 碎片，增的多是片假名词）。
2. **段级残留检查对"整段艺术假名"天然失明**：`kana_runs`/`real_kana` 都按设计排除 ART_HIRA/ART_KATA（防 art 行误报）→ 规则段必须另走严格口径，
   否则漏译两头都拦不住。规则段还应有"原样照抄即失败"的硬检查（唯一豁免：专名池 = 全局 `KNOWN_NAMES` ∪ 作品术语表日文侧）。
3. **规则行校验失败必须回退整行协议**：`process_chapter` 的 `fallback_todo`(B2) 长期是**死代码**（无人 append），
   而 mixed 段级失败行按 2026-09-01 的设计只落 `review_inline` 不重译 → 失败行会**静默原样留在交付物里**（实测 3 章 9 行，含 5 行真台词）。
   规则抠段的行本来来自"meta 不可用"的 mixed 行，整行协议正是它们规则关闭时的路径（有 art 描边守恒校验兜底），回退安全。

**验收口径教训**：A/B 的行级差集有随机成分（同一行 `seg_shrink` 失败与否取决于模型输出长度，两次跑法互换失败行），
验收要看**机制是否生效**（事故行有没有进段级协议、失败有没有回退、debug 日志事件分布），不能只看"B 未译而 A 已译"的行数。

**结论**：`AA_MIXED_SEG_RULE` 校验补齐后仍**不上线**——同环境 3 章 A/B 反而 **+2.1% 成本**（接管 2~3 行/章 vs 607 次 `seg_shrink` 重试）。
要上线先解决 `seg_shrink` 过严（现阈值：译文比原段窄 >4 格即判"吞字"重试）。
