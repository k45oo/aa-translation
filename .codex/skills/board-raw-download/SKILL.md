# 揭示板原始数据下载与解析（2ch系 / zerochan系改変板）

## 触发
- 镜像站（r401 分类页 / yaruobook.jp / yaruomatomex 等）对某连载作品**只收录部分章节**，
  用户提示「r401 没有收录」「需要在原始揭示板中找」「历史贴地址可能需要转换」。
- 作者把正篇连载藏在**自投的雑談所スレ**里（楼内章节、无固定楼层），需先下载全部原创贴。
- 典型：`akari_kurutta_mura`（紲星あかりは狂った村）r401 cid=25548 只到第10话，
  但正篇连载到第15话+，作者=コンプレックス◆JWKY.d5ark，揭示板=yarufox.sakura.ne.jp(/FOX)。

## 本项目已落地：`scripts/runner/board_runner.py`（首选，别再手写爬虫）
```
python scripts/runner/board_runner.py --board FOX --match <标题关键词> [--author <trip>]
    [--dir <作者_作品短名>] [--title <作品名>] [--work <作品id>] [--label <连载标签>]
    [--host http://xxx] [--kako-from 1746] [--kako-to 1774] [--scan-kako] [--force] [--allow-mixed] [--json out.json]
```
- 落盘 `揭示板/<目录>/<N>スレ目_<eid>.dat`（UTF-8 重写）+ `index.json`
  （`slaves[] = {label,eid,title,res,bytes,ts,file,url,note,src}`，口径 = 工作台 `logic.board_slaves`）。
- 发现顺序：`subject.txt`（活跃）→ `index.json` 里已知 eid（贴变归档后 **eid 不变**，直构造 kako 路径重抓）→
  `--scan-kako`/本地无 index.json 时扫 kako 索引；HTTP 走磁盘缓存 `揭示板/.cache/<board>/`（TTL `AA_BOARD_CACHE_TTL` 默认 24h）
  → 重跑/断点续跑几乎零请求；**顺序抓 + 间隔**（`AA_BOARD_DELAY` 默认 0.3s）。
- 工作台：`/board` 首页「＋ 添加 / 更新揭示板」表单 + 每行/作者页「↻ 更新」按钮（入队 `board` 任务，进度就地显示）。
- **范围**：`--kako-from/--kako-to` 是 **eid 前 4 位**（dir1）；新作首次收录要按作品起始时间估区间
  （`datetime.fromtimestamp(eid)`；实测 2025-04→2026-03 的 47 贴落在 dir1 1746~1774，扫 29 个 dir1 ≈ 2 分钟含缓存）。

### ⚠ 同一作者多作品必须各占一个目录（实测事故）
NEO坊 ◆LXwkncCAp. 在 FOX 有《この素晴らしいシンオウに祝福を！》(120 贴) 与《ポケの子（？）》(47 贴)。
第二次用**同一个 `揭示板/◆LXwkncCAp/`** 跑 ポケの子 → 旧 120 贴被**重新编号**（标签 1スレ目… 被 ポケの子 的贴占用，
原 `前スレ（キャラ作成〜第8話）` 等标签丢失）、`index.json` 被覆盖（靠旧文件名 + dat 才复原）。
- 目录命名：`<作者trip>_<作品短名>`（如 `◆LXwkncCAp_ポケの子`）。
- runner 现有三道闸（`--allow-mixed` 才放行）：
  ① 目录里有不属于本次范围的 `.dat` → 拒；② 新标签与已有贴重名（不同 eid）→ 拒；
  ③ `index.json` 记的 `match`/`work_title` 与本次不同 → 拒。
- 已知 eid **沿用文件名里的原标签**（勿按命中顺序重编号）；标签来自标题假名编号，解析不出才用顺序兜底。

## 站型识别
yarufox.sakura.ne.jp 是 **zerochan 系 BBS**（页脚 `READ.CGI - 0ch+ BBS 0.7.4 20131106`）。
板路径 `/FOX/`。数据源两种：
- **活跃贴**：`https://yarufox.sakura.ne.jp/test/read.cgi/FOX/<eid>/`
- **已归档贴**：read.cgi 只返回 **~1268B** 跳转页（`<title>隊長！過去ログ倉庫に</title>`），
  正文在 `kako/` 归档目录。

## 关键：kako 归档地址转换规则（直接构造，勿依赖跳转页解析）
已归档贴真实地址 = `https://yarufox.sakura.ne.jp/FOX/kako/<eid前4位>/<eid前5位>/<eid>.<html|dat>`
- eid=1624183408 → `kako/1624/16241/1624183408.dat`
- eid=1593190227 → `kako/1593/15931/1593190227.dat`
- `.dat` = 纯文本（2ch dat 标准格式）；`.html` = 完整页面（含帖头样式）。
- **cross-check**：跳转页正文会给出确切归档链接（`/FOX/kako/...`），与上述规律一致。
  正则解析：`/FOX/kako/(\d{4})/(\d{5})/(\d+)\.(?:html|dat)`。

## 枚举「某作者/某作品的**全部**スレ」（kako 索引三层爬）
当一个作品连载 100+ スレ 且镜像站/维基只列到一半时，用板自身的归档索引全量枚举：
1. `GET /FOX/kako/` → 列出**目录1**（= eid 前 4 位，如 `1656/`）；
2. `GET /FOX/kako/<d1>/` → 列出**目录2**（= eid 前 5 位，如 `16567/`）；
3. `GET /FOX/kako/<d1>/<d2>/` → **表格行 = 该目录下全部贴**，格式
   `<td>KEY</td><td><a href="<eid>.html">标题</a></td><td>时间戳</td>`（正则
   `<td>(\d+)</td>\s*<td><a href="(\d+)\.html">(.*?)</a></td>\s*<td>(\d+)</td>`）。
- 目录1 范围按 eid 时间戳估算（2022-07 eid≈1656xxxxxx，2025-04≈1745xxxxxx）→ 只爬需要的区间。
- 规模参考：111 个目录1 / 934 个目录2 / 2235 个贴；顺序抓约 20 分钟。**先看 `/FOX/subject.txt`**
  （活跃贴清单，`<eid>.dat<>标题 (回复数)`）确认没有还在活跃的本贴，没有则全在 kako。
- **⚠ 该站并发会返回 404/空体**（实测 3~8 并发时 dir2 页 100% 失败，顺序 100% 成功）——
  **必须顺序抓 + 每请求 0.2~0.5s 间隔**，配磁盘缓存（URL→文件）以便断点续跑。

### 标题里的和数字假名（スレ目编号）
该板スレ 标题用假名拼数字：`～…を！そのごじゅうななっ！～` = 57、`そのひゃくじゅうよんっ` = 114、
`そのふぁいなるっ`（最终）。**解析要按 せん/ひゃく/じゅう 拆分求和**，不要用「遇单位就累乘」——
会把 `ひゃくじゅう`（110）算成 100×10=1000（实测踩到，119 贴里 10 个编号错成 1000~1009）。
`そのじゅうっ`（10）这类**后缀为 0 的余数为空**，要按 0 处理，否则整串解析失败。

### 标题枚举会漏「前スレ」——开场常藏在上一部作品的贴里
作者往往把新企画直接开在**上一部作品的贴/杂谈所**里（该贴标题里当然没有新作名），
所以「标题含作品名」只能拿到新作**独立标题的第一贴**，开头几话全在上一贴。
- 补齐依据：镜像站（yaruobook 等）章节页的首条 `NNN ： 作者 ： 时间` 里的 **NNN 就是源贴真实 res 号**
  （同一贴内连续递增，跨贴归 1）。把各章 res + 时间戳排序，就能看出边界：
  `res 2775(06/23)…res 4982(07/02, 第8話)` → 旧贴；下一章 `res 224(07/03)` → 新贴。
- 找旧贴：新贴 OP 里的引用链（如 `…/test/read.cgi/FOX/1654611861/3284より`）直接给出 eid；
  或拿枚举结果 `all_rows.json` 按 eid 反查标题。
- 落盘标签用 **`前スレ（〜第N話）`**（不带 `Nスレ目`）——工作台 `board_slaves` 按
  `(label 里的スレ目号, eid)` 排序，没号的会归 0 而排在最前，正好在 1スレ目 前面。
- **完整性验收不能只比数量**：逐章拿 `(res 号, 时间戳)` 去候选贴的 dat 里定位（`res_map[res] == 章节时间戳`），
  810/810 全命中才算无缺口（只按时间窗口归属会把「新贴已建、旧贴还在投稿」的章误判）。

## 探针层次（先探测再决定抓哪些）
1. 先试 `https://yarufox.sakura.ne.jp/FOX/dat/<eid>.dat`（活跃贴直接命中）
2. 404 → 抓 `test/read.cgi/FOX/<eid>/`：
   - 返回 **>100KB** = 活跃贴完整 HTML（当前连载贴，用 `/dat/` 或 HTML 均可）
   - 返回 **~1268B** = 归档跳转页 → 解析 kako 地址 → 拼 dat 再抓
3. 用 **5-6 并发**抓全部贴（作者全スレ链一次几十 MB，如 14 贴共 ~107MB）

## CP932 解码坑（必踩）
- dat/目录 HTML 是 **Shift_JIS/CP932**。`decode("cp932")` 成功，`decode("utf-8")` 必失败
  （title 显示 `�yR-18�z` = CP932 被当 UTF-8 读的结果）。
- **浏览器「另存为」保存的本地 HTML 是转码破坏版**（cp932/utf-8 都解不出，约 3160 字节处
  报 `illegal multibyte sequence`）——**不要当数据源**，一律重新抓 dat。
- 尾部余字节报错：用 `decode("cp932", errors="replace")` 容忍破损。

## dat 格式解析
2ch dat 每条 res = `名前<>mail<>日期时间<>本文<>`，`\n` 分隔 res。
- 首条 res 的 `日期部分` 用正则 `\d{4}/\d{2}/\d{2}\(\S\) \d{2}:\d{2}:\d{2}`。
- **正文含各作者 ID**（如 `コンプレックス ◆JWKY.d5ark` 是作者 ID）；
  贴内引用 `>NNN`，跨贴锚定/定位章节靠作者 ID + 时间戳 +「第N話」标题。
- 本文一行一 `<br>`，整条 res 是长字符串 → 用 `<br>` 切行，不要按 `\n` 切正文。

## スレ编号校准（重要坑：eid ≠ スレ号）
用户给的「雑談所N」编号可能与首发贴内标题【Nスレ目】不一致。
- 真实序列以**作者贴内标题【Nスレ目】+ 首楼时间戳**为准，eid 顺序不可靠。
- akari_kurutta_mura 作者全部 14 贴校准（本项目已验证）：
```
1スレ目=1586077912  2020-04-05 (标题无数字,最早)   8スレ目=1644071501
2スレ目=1593190227                                 9スレ目=1653743293
3スレ目=1600163683                                 10スレ目=1665574469
4スレ目=1606558564                                 11スレ目=1679925529
5スレ目=1616760914                                 12スレ目=1700748580
6スレ目=1624183408 (本地已有)                       13スレ目=1722166694 (=用户称「前スレ」)
7スレ目=1633000872                                 14スレ目=1761748367 (活跃贴, 2115 res)
```
- 每个已归档贴 **5001 res**（reveal板 1000 res/页 分页，0001-1000 / 1001-2000 / ... 拼成整贴）。
- 落盘（本项目口径）：`揭示板/<作者或 <作者>_<作品短名>>/<N>スレ目_<eid>.dat`（UTF-8 重写，易检索）
  + 同目录 `index.json`（eid↔スレ号↔首帖时间↔res数）——工作台 `logic.board_slaves` 直接读它（`slaves[]` + `label/eid/res/ts/file`）。

## 正篇章节→貼 定位（后续步骤）
雑談所贴内**不直接写「第N話」章节标题**（正文搜不到「第11話」等），作者把正篇
当作独立投下或嵌在楼里，无固定楼层。定位第N話需：全文扫描「第N話」标题 + 作者 ID
+ 时间戳跨贴锚定。数据全部落盘后据此扫描即可。
