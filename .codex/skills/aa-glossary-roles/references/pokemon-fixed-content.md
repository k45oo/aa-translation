# 宝可梦链：固定内容族清单 / 词源覆盖 / 零模型直出判定

适用：`pipeline=pokemon` 的作品（`pokemon_runner` → 预填四轨 `pokemon_fixed.match_line` → 通用链
`translate_runner` 送模型的那份文本先过 `pre_terms.apply`）。
用途：用户提出「某类行应该固定替换、不该送模型」时，先按本文量测现状，再决定补词源还是加模板。

**关键词源事实**：本作 wiki `术语表.json` 的 `terms[]` 带 `desc`(日) + `desc_zh`(中)，且招式/特性/潜能条目的 `desc`
与章节行说明**归一空白后逐字一致** → 这些行可零模型直出。**潜能条目的 `jp` 带『』**（`"jp": "『気合い』"`）——
按裸名查会 100% miss，是先量测时最容易得出错误覆盖率的原因。

`desc_zh` 是**生成物**（wiki 页面机翻后抽取，非人工确认）→ 当固定内容用必须过护栏（残留假名/照抄），不合格交回模型。

## 二、零 API 摸底流程（改规则前必跑）

1. **族统计**：正则扫 `aaManga/<work>/aa/*.txt`，按族计数 + 名称 `Counter` 去重；同时记「首次出现的原文行」当上下文。
2. **名称覆盖**：逐名查四源并按优先级合并——`本作wiki 术语表 terms`（含『』原样）> 本作wiki `人工修正.json.本地译名`
   > 通用 `ポケモンAA术语wiki`（`术语表.json` + `官方译名对照.json`）> 作品表 `work/glossary_<work>.json`。
   输出「全无」名单 = 待补清单（场地名/官方特性最常集中在这里）。
3. **逐行判定**：固定表/模板命中 → 直出；否则算残留片段（挖掉替换跨度后剩余）→ 含假名或汉字 = 送模型。
4. **渲染人工确认**：`python scripts/tools/gen_pre_terms_render.py --work <id> --base eid,eid`（零 API，替换后↔原文对照，
   命中处黄底）→ 在该页上加逐行「直出/送模型 + 残留片段」，交用户确认判据准确后再改管线。

配套脚本自带验收：`gen_pre_terms_report.py --work <id> --base <eid>`（词表/逐行对照/固定表预填/术语落地质量）。

## 四、落点（按现有机制，方案层，待用户逐项确认后落地）

- **词级**（名称、程度副词、固定短句）→ `补充术语.json` 的 `terms` / `works.<作品名>.terms`（成批补，受本章语料过滤）。
- **整行系统行**（`◎フィールド：《{场}》（効果：>>{N}）`、`◎今回の編成（戦闘準備：>>{N}）`、`◎当スレwiki【…】`、
  `（指示の前にデータを解析できます）`）→ `补充术语.json` 第五段 `模板`（`tpl_templates()` 编译成锚定正则，整行零模型，
  加条目不用改代码；模板命中打 `no_art` 跳过 art 锚点校验，宽度按段尾补位）。
- **带大段说明的行**（`『名』…　　　说明`、`【特性】名…　说明`）→ 固定表 struct 轨（本作 wiki `desc`/`desc_zh` 派生，
  量级 7708 行，手写不现实）；`STRUCT_RE` 目前只认 `『』` 形，`【特性】` 形需要再加一种前缀。
- **翻译时是否继续注入术语表**（用户提过「翻译（不使用术语表）」）——属决策项：注入对已由 pre_terms 强制替换过的词是冗余，
  但 `glossary_prompt_hint` 还带章节简介/人物知识库，停用范围要先确认，别一刀切。
